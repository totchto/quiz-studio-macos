# Работа с Quiz Studio

## Начало задачи
- Прочитай `PROJECT_CONTEXT.md` один раз при начале новой сессии. Затем используй текущий контекст, не перечитывай его на каждом шаге.
- Проверь `git status --short`. Сохраняй чужие и незакоммиченные изменения.
- Контекст других открытых проектов, включая `faceminermodloader`, не относится к квизу. Не исследуй его без запроса пользователя.
- Файлы `sources/` родительского ChatGPT-проекта — только для чтения.

## Экономное исследование
- Начинай с `rg -n` по нужному символу и небольшого фрагмента файла. Не читай целиком `main.swift`, README или историю чата ради одной функции.
- Для обзора изменений используй `git diff --stat`, затем diff конкретных файлов или функций.
- Не сканируй `.build/`, `dist/`, `Downloads/`, исполняемые компоненты и пользовательские каталоги без необходимости.
- Находи только нужные инструменты; не выводи весь каталог инструментов, полные API-ответы или деревья интерфейса. Из ответов извлекай необходимые поля.
- Используй Git/API/CLI, когда они доступны и авторизованы. Для UI-действий используй CUA; проверяй конкретный экран, ограничивай вывод AX. Не запускай браузер или REA для обычного анализа исходников.

## Реализация и проверка
- Выполняй согласованную задачу полностью; экономь на повторениях, а не на необходимой работе.
- Начинай с целевых проверок из `PROJECT_CONTEXT.md`. Расширяй их при общих изменениях, ошибках или неустранённых рисках.
- Логи направляй во временный файл; показывай итог и ошибки, а не все предупреждения и команды компилятора.
- Успешную проверку повторяй после относящихся к ней изменений, а не просто из-за следующего шага задачи.
- Перед релизом выполни одну итоговую сборку и релевантный набор проверок. Переиспользуй результаты для неизменившегося кода, явно отмечая ограничения проверки.
- Для изменений только документации достаточно проверки ссылок/путей и `git diff --check`; приложение не пересобирай.
- Не дроби задачи между агентами без явного разрешения пользователя или применимой инструкции.

## Состояние и публикация
- Обновляй `PROJECT_CONTEXT.md` после изменения архитектуры, команд проверки, публикации или появления существенного ограничения. Храни текущие факты, а не журнал действий и логи.
- Коммит, push и релиз делай по запросу пользователя. Пользовательские квизы, паки, банк и архив игр не публикуй без отдельного разрешения.
- В финале кратко укажи результат, проверку, существенные ограничения и ссылку на артефакт, если он создан.
